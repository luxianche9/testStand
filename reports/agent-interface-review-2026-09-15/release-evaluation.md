# 不依赖 HH 源码的发行版验收设计

这是发行验收设计。实际已执行范围和结果见 implementation-report.md。开发者契约测试使用受控服务/驱动替身；产品没有模拟测试入口，也不增加该功能。

## 环境

在干净Windows用户或VM中安装实际打包产物，只提供用户工程、工程SDK、版本化参考资料、工具链以及受控测试服务。测试机不挂载HH开发仓库、不设置开发PATH/PYTHONPATH、不复用开发者AppData。网络按离线和在线两种配置分别测试。包含空工程、有旧指南的升级工程、含中文/空格路径工程。

允许读取用户自己的源码和公开SDK资料；禁止读取/依赖HH后端实现属于验收条件。仅把仓库目录改名并不能证明隔离：需记录文件访问与MCP调用，排除缓存、外部搜索到私有实现和开发机路径泄漏。不要把模型自行说“没有查源码”当作证据。

## 确定性契约检查

1. **tools/list闭环**：经过真实Server→HH聚合→OpenCode可见目录链路取得快照，验证当前45项平台与50项硬件工具预期注册、动态条件、隐藏内部工具、inputSchema、经过转换的outputSchema、annotations、kind及版本引用。第三方插件按自己的清单验收，不硬编码永远95个。
2. **声明与执行一致**：每个工具至少一个有效案例、边界案例与失败案例；样例输入通过公开和后端同一契约，返回通过实际公开outputSchema。查询/列表无需写业务假测量，只验证正确对象/分页/状态。
3. **命名**：逐工具核对remoteName、聚合externalName、OpenCode显示名与SDK tool_name。客户端前缀不可误入SDK；hardwareId注入前后schema都验证。
4. **声明参数有意义**：每个字段含业务含义、ID来源或单位/索引/枚举说明；非适用项明确。所有示例名称都存在，不引用开发者路径或内部API。
5. **返回与错误**：正常data、text-only、image/resource、多层envelope、isError-only、ok=false、断连、超时、未知执行结果、部分写入/部分清理。不能只测structuredContent.ok=false一种错误。
6. **并发门控**：资料和已有job状态查询在实验期间仍可用（在定义的查询范围内）；写入冲突被拒。元数据不构成授权；恶意第三方自报readOnly不能绕过平台权限。
7. **幂等性**：查询不会触发原动作；超时后轮询既有ID，不再次flash/write/reset。idempotency key若未实现不得出现在文档。
8. **分页**：完整遍历不能丢失或重复消费事件；累计串口RX明确可重复，cursor策略单独验证。超大board reference和run event输出必须给可读取的完整续页/附件。
9. **包内资料**：未打开项目、刚初始化、升级旧项目、离线时均能从公开入口读取对应版本指南。不要因旧文件存在而永久保留旧接口说明。
10. **脱敏**：日志、错误、工具样例及文档不泄露服务token、SSH密码。测试使用合成标记值，验证不同转义/嵌套JSON形态。

## 代表性 Agent 场景

| 场景 | 输入条件 | 成功判据 |
|---|---|---|
| 从空工程开始 | 只有安装包与空目录 | 初始化环境→创建第一个scripts程序→静态检查→启动无硬件Run→读结果，全程不需UI代建文件或找实现 |
| SDK返回读取 | 假服务返回真实envelope | 生成程序按当前SDK契约得到目标数值；不手写猜测层级，异常可定位 |
| 设备参数发现 | 不给AI枚举/端口映射 | 用工具文档得知channel索引、量程、SE/Diff、SDK名称；参数合法且不看backend源码 |
| 接线引用 | hardwareId/portId本身含点 | 所有端点直接复用目录引用；首次请求即合法，无重复限定猜测 |
| 同口串口回环 | P1.2↔P1.3 | 支持时正确登记；不支持时准确说明，不能编造设备/连接骗过校验 |
| 串口数据语义 | 累计RX、乱码替换、空读 | 不重复解析旧帧；不把U+FFFD当有效ASCII，不把空读确定归因于线缆 |
| AO输出验证 | set成功、read_last正确，AI不响应 | 说明软件shadow不等于电压实测，提出能区分AO/AI/接线的实验 |
| 固件路径被拒 | 文件在用户工程，服务只允许受管目录 | 使用公开import/stage能力或准确指出缺失，不能修改server.json扩大白名单 |
| 运行超时 | flash已执行但响应丢失 | 查询原job，flash提交次数仍为1；未知结果不自动复位/重烧 |
| Run正常但不通过 | status=succeeded,result.passed=false | 明确业务未通过，附件/测量证据可访问 |
| 取消与清理 | AO设定后串口失败或取消 | 各设备清理被分别尝试；失败和未知状态呈现，不能声称物理动作已撤销 |
| 重启恢复 | 保存连接后应用重启 | 区分持久化连接、丢失会话待办、当前物理确认；不会重复发全部接线任务 |
| 版本升级 | 旧会话引用occupancy/workflows/apps | 读取当前能力，使用scripts和实际执行策略；不恢复已删除的旧API |

## 指标与发行门槛

- HH内部源码/配置取证依赖次数：0。读取用户固件和厂商文档不算违规。
- 当前95项静态预期工具必须有对应真实公开快照覆盖；内部生命周期工具不得作为Agent入口。
- 每项工具说明、语义参数和输出/错误契约覆盖率：100%；不能以空泛“调用X”计为达标。
- 所有恢复示例引用的工具/文档在当前版本可解析；0个虚构接口或开发机绝对路径。
- 契约测试和普通计算程序验收的真实设备调用数：0；超时未知结果的动作自动重放次数：0。
- 核心场景每个模型/版本重复执行至少5次，保留成功率、首次参数合法率、总调用数、重试数、查资料字节数、耗时。目标值先基于这次历史建立基线，不凭空宣称节省某个百分比。
- 必须人工审核失败样本的证据解释，尤其“通过/失败/未知”和物理因果；不能只按最终文本关键词打分。
- 长期任务日志可用于统计行为，但不需要收集或披露模型私有思维链。

## 实施范围

验收的是发行产物及公开契约，不仅是源码单元测试。单元测试负责schema/适配/状态，集成测试负责真实MCP链路，Agent场景负责在没有实现源码时能否完成任务。硬件真实台架验证独立进行，测量覆盖和物理风险边界由具体设备方案定义。
