# 远程任务提示词

在台架电脑上拉取仓库后，在仓库根目录启动 Claude Code，把下面整段粘贴进去。

---

你在 HardwareHarness 仓库根目录，运行在装有 PCI-1710L、PCI-1762、PCI-6208V、CP-118U-I 四块卡的台架电脑上。这次任务是把项目从"远程设备服务"架构重构为"单机插件"架构。

1. 先完整阅读 `doc/plan/单机插件化重构.md`。它是本任务唯一的任务说明，里面的决策 D1–D7 已由用户确认，不要再讨论。
2. 按任务书第 5 节从阶段 0 开始逐阶段执行：
   - 每阶段先重新扫描确认要删、要改的位置（任务书里的行号只是线索）；
   - 完成后跑第 4 节验收命令，全部通过后提交，提交信息用中文并标明阶段号；
   - 在任务书第 9 节"进度记录"追加一行。
3. 硬件：允许你直接执行任何硬件操作，但每次真机测试结束都必须把输出恢复到 `safe_state`。
   - PCI-6208V 板载 ±15 V 已坏，AO 读数约为 0 V，这是已知硬件故障，不要在代码里追查。
   - 线缆目前全部拔掉；需要回环接线时停下来告诉我。
   - 本机旧版设备服务以计划任务形式运行（`\HardwareHarness\`），阶段 0 先停掉并禁用开机启动，保留安装目录用于回退。
4. 禁止事项：
   - 不要提交 `server.json`、token、密钥；
   - 不要修改 FireDAP（`mcp_servers/servers/firedap`）本身；
   - 不要重新引入租约、设备图片、远程部署；
   - 不要写数据迁移或兼容代码。
5. 遇到任务书第 8 节的决策点（Q1 CAN、Q2 FireDAP、Q3 驱动权限），或者遇到判断不了原因的验收失败，就停下来简要汇报，并给出你的建议。
6. 每个阶段结束后用中文简短汇报：做了什么、验收结果、提交号、下一阶段。然后不必等我确认，直接继续下一阶段；只有遇到第 5 条的情况才停下。

现在从阶段 0 开始。
