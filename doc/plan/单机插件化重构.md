## 0. 背景与已定决策

项目原设计假设"测试终端"和"测试资源"分处两台电脑：每块卡是台架电脑上独立的 FastMCP HTTP 服务，终端经 SSH 部署、经 HTTP/SSE 调用，并用租约防止多终端争用。实际使用是**一台电脑同时驱动全部测试资源和测试终端**，资源很少变动；"测试资源通用化"是为了以后能加新类型的资源，而不是为了在多个终端之间共享、交换资源。

## 1. 目标架构

```
Electron（只负责显示：窗口、原生对话框）
   │  启动 Python；stdout 一行握手 {port, token}；关闭 stdin = 退出
   │  渲染进程直连 HTTP + SSE（127.0.0.1，单 token）
Python 后端（单进程）
   ├─ 应用层（@operation 注册表）/ 测试引擎 / 判定 / 记录
   ├─ Agent MCP 网关（127.0.0.1:8000，给 OpenCode/Codex，保留）
   ├─ OpenCode 进程管理（从 Electron 主进程迁来，阶段 6）
   └─ 设备宿主：按实例配置加载 N 个 Device 插件
        ├─ isolation: inproc     → 直接调用（CP-118U-I / PCOMM）
        └─ isolation: subprocess → stdio JSON 行子进程
              ├─ PCI-1710L / PCI-1762：hwcli_*.exe（现状已是）
              └─ PCI-6208V：PCIS-DASK（加载时会写 stdout，必须隔离）
```

插件模型（参考 OpenHTF plugs、QCoDeS Station、ros2_control、OpenTAP，结论见第 7 节）：

- **类型发现**：适配器包在 `pyproject.toml` 声明 entry point：
  `[project.entry-points."hardwareharness.devices"] pci6208v = "hh_adapter_pci6208v:DEVICE"`。
  后端用 `importlib.metadata.entry_points(group="hardwareharness.devices")` 列出可用类型。
- **实例配置**：沿用后端硬件记录（`device_store`），收敛为 `{id, type, settings, mode: real|sim}`。同型号多块卡 = 多个实例。
- **隔离声明**：`Device` 类属性 `isolation = "inproc" | "subprocess"`，由插件决定，上层无感。
- **操作只定义一次**：`@tool` 的签名与 `operationSemantics.kind` 同时生成界面表单 schema、Agent MCP 工具、测试步骤目录。
- **SDK 定位**：从"FastMCP 设备服务器"改为"设备插件 SDK"，去掉 FastMCP / Starlette / uvicorn 依赖。
- **时钟**：同一进程同一时钟，流不确定度为 0；SDK `now_ms` 与后端 `backend_ms` 必须是同一个时钟源。

### 阶段 4：设备插件化（D6）——本次核心

目标：后端按实例配置直接加载适配器，不再经 HTTP。先**与旧 HTTP 传输并存**，四块卡在真机上验证通过后，阶段 5 再删旧路径。

1. **SDK 插件宿主**
   - 把 `DeviceService`/`HardwareManager` 中与 HTTP 无关的部分（内建工具、`_operate`、信封、`operationSemantics`、transact、流读取、生命周期、`io_lock`）整理为可在进程内实例化的 `DeviceHost`（名字可自定）：一个实例对应一块卡。
   - 新增 entry point 组 `hardwareharness.devices`，四个适配器 `pyproject.toml` 声明；`load_device` 改为优先查 entry point。
   - `Device` 增加 `isolation` 类属性。
2. **stdio 隔离助手**
   - 以现有 `jsonline.py` 的 `JsonLineCli` 为基础，提供通用"在子进程里运行一个 Device，父进程持代理"的机制：父子间 stdio JSON 行协议；子进程 stdin EOF 时执行 `safe_state` 后退出；父进程用 Windows Job Object 保证子进程随后端退出。
   - 子进程内 stdout 只给协议用，驱动的打印重定向到 stderr。
   - PCI-6208V 设为 `subprocess`（PCIS-DASK 加载时写 stdout，会污染后端给 Electron 的握手行）；CP-118U-I 设为 `inproc`；1710L/1762 本身已通过 `hwcli_*.exe` 子进程，适配器设 `inproc` 即可。

## 7. 调研结论（插件化参考）

| 维度 | 业界主流 | 本项目采用 |
|---|---|---|
| 驱动定义 | 设备基类 + 声明式操作（OpenHTF `BasePlug`、QCoDeS `Instrument`、Tango `@command`、OpenTAP `Instrument`） | 现有 `Device` + `@tool` |
| 发现 | 代码层 entry point/插件扫描列类型，配置文件决定实例（QCoDeS Station YAML、ros2_control pluginlib + URDF、Home Assistant manifest + config entry） | entry point + 硬件实例记录 |
| 进程 | 默认进程内，只为隔离才子进程（TestStand Python 适配器、msl-loadlib） | `isolation: inproc/subprocess` |
| 子进程通信 | stdio/管道，父进程管寿命 | stdio JSON 行 + Job Object |
| 仿真 | 同接口另一实现（ophyd-async `mock=True`、ros2 `GenericSystem`、pyvisa-sim） | `select_driver(real, sim)` |
| 生命周期 | 显式状态 + 必有安全收尾（OpenTAP `Close()`、PyMeasure `shutdown`、HA `NotReady` 退避重试） | open/safe_state/重试/退出 safe_all |
| 并发 | 每设备串行；序列运行时独占（OpenTAP ResourceManager） | `io_lock` + `ExecutionCoordinator` |

单机场景下没有项目把每台设备做成网络服务；Tango/EPICS 网络化是为多客户端、多主机、7×24 大装置。

按能力抽象的 HAL（NI 推荐：测试序列写"AO/DO"而不写型号）暂不做，等出现同一能力两种卡互换的需求再引入。

参考：OpenHTF plugs <https://www.openhtf.com/plugs>；OpenTAP Resources <https://doc.opentap.io/Developer%20Guide/Resources/Readme.html>；NI HAL/MAL <https://www.ni.com/content/dam/web/scene7/white-papers/22/07_Hardware%20and%20Measurement%20Abstraction%20Layers_LTR_EN_WR.pdf>；QCoDeS Station <https://microsoft.github.io/Qcodes/examples/basic_examples/Station.html>；ophyd-async <https://blueskyproject.io/ophyd-async/main/explanations/design-goals.html>；ros2_control <https://control.ros.org/jazzy/doc/ros2_control/hardware_interface/doc/writing_new_hardware_component.html>；Python 插件发现 <https://packaging.python.org/en/latest/guides/creating-and-discovering-plugins/>；msl-loadlib <https://msl-loadlib.readthedocs.io/en/stable/interprocess_communication.html>；MCP 传输 <https://modelcontextprotocol.io/specification/2025-11-25/basic/transports>。
