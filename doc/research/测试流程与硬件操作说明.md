本文从测试台架软件的视角，说明四个项目怎样调用硬件，以及如何组织测试。全文采用通用电子设备测试表述，测试项使用中性编号，只记录台架侧的配置、激励、等待、采集、判定、记录和恢复操作。

硬件型号、数量、SDK（Software Development Kit，软件开发工具包）及底层接口见配套的[硬件资源与 SDK 清单](E:/Project/uniTest/doc/research/硬件资源与SDK清单.md)。本文重点回答这些接口在测试过程中实际用于做什么。

## 1. 阅读口径

- A、B、C、D 分别代表四个项目。编号用于本文整理，不等同于软件菜单编号、数据库 StepID，也不表示四个项目之间的执行顺序。
- 同一台架操作在不同通道、额定档位或软件版本下的变体适当合并；准备、供电监视、手动操作和保留代码另行说明。编号数量不能当成原软件测点数量。
- “采集协议数据”指上位机从串口、总线或解析缓存取数；“独立采集”指采集卡或仪器直接测量电气量。两者在表中分别标明。
- 不列原专用业务名称、命令载荷、专用动作时序，以及被测对象接受激励后的具体动作、内部处理和预期业务行为。
- 本文依据现有源码和随附配置核对，未启动测试软件连接实物。表中的判定方式是代码实现，不代表已经完成实机验收。

## 3. 项目 A：MPro

### 3.1 硬件在流程中的职责

| 硬件 | 台架实际操作 | 在流程中的位置 |
| --- | --- | --- |
| SPDT4801 继电器卡 | 接通、断开单路或多路开关，组合外部离散条件，操作复位线路 | 测试准备、开关类项目、部分项目之间的恢复 |
| RSX8 串口卡 | 收集串口文本；按提示发送菜单选择及诊断命令；在两个 RS485 通道之间发送、接收测试数据 | 大多数测试项的控制和结果通道 |
| 28DC-JS 电源及状态接口 | 控制电源输出；读取电压、电流和光耦输入状态；电压或电流超限时调用关电源操作 | 独立供电管理与持续监视；部分数字状态判定的采集来源 |
| 主机网卡 | 选择、配置网络接口，调用系统 ping 检查连通性 | 网络类项目；另有 Qt UDP 通信路径 |

供电开关和电气监视由独立界面、接收处理逻辑承担。测试队列启动本身不能等同于一次完整的电源初始化。UDP 接口的存在也不能证明每项网络测试都通过 UDP 完成。

### 3.2 实际测试流程

```text
选择测试模式、项目和循环选项
  → 清理队列、串口缓存和本轮结果，设置继电器初始状态
  → 取队首项目，必要时插入串口诊断会话准备项
  → 定时检查当前步骤：发送命令／切换继电器／发起网络检查
  → 读取串口缓存、电气状态或网络检查结果
  → 记录结果，或按单项超时分支记录异常
  → 按该项完成路径复位线路、清缓存，或保留当前会话
  → 下一项；队列结束后重新循环，或保存结果表
```

源码使用周期定时器推进测试，并为不同项目设置超时。正常完成与超时通常都会移出队首、继续下一项。部分连续诊断项目共用一个会话，因此存在“保留会话和缓存”的完成路径。

### 3.3 编号测试项

| 编号 | 使用硬件 | 台架侧操作流程 | 采集与判定方式 |
| --- | --- | --- | --- |
| A-01 | RSX8；必要时使用继电器准备线路 | 接入所选串口会话，按提示发送选择命令，提取软件标识、版本或日期文本 | 在串口缓存中查找指定字段，记录字段或超时；不同串口的同类流程合并列示 |
| A-02 | RSX8 | 发送预置版本查询或菜单命令，读取另一组逻辑版本信息 | 提取并记录文本字段；未调用相关器件的独立 SDK |
| A-03 | RSX8 | 在诊断会话中依次发送计算、存储、计时等检查请求 | 匹配串口中的结果文本或数值字段，记录通过、失败或超时；本文不展开各请求的内部执行内容 |
| A-04 | SPDT4801、RSX8 | 设置一组开关条件，接通后释放第一路复位线路，再采集串口文本 | 按现有文本检查逻辑记录结果；完成后进入下一项 |
| A-05 | SPDT4801、RSX8 | 设置所需开关条件，接通后释放另一条复位线路，再采集串口文本 | 与 A-04 使用不同开关路径；结果仍由串口信息判断 |
| A-06 | SPDT4801、RSX8 | 切换多组离散开关组合；每次切换后发送读取请求 | 从串口记录中提取状态，并进行软件比较 |
| A-07 | RSX8、28DC-JS 状态接口 | 经命令串口发送两组预置测试设定，分别读取光耦输入状态 | 使用台架接收到的数字状态做分项判断；与 A-06 位于同一组合测试函数内 |
| A-08 | 主机网卡、RSX8 | 经串口完成会话准备，按两个接口分支配置网络访问并执行 ping | 根据主机命令输出记录连通性；未测量吞吐率或网络性能曲线 |
| A-09 | 主机网卡、RSX8 | 经另一串口路径完成准备，对配置的网络地址执行 ping | 记录连通性和超时；测试准备路径与 A-08 不同 |
| A-10 | RSX8 的两个 RS485 通道 | 清理接收数据，在两个通道分别发送测试字符串，再读取对应接收缓存 | 比较测试字符串是否出现，分别记录两个方向的结果 |
| A-11 | RSX8 | 从命令串口发起接口诊断请求，读取诊断文本 | 由串口结果文本判定；这类项目不能等同于上位机独立测量总线电气指标 |
| A-12 | RSX8 的两条串口链路 | 协调两路诊断会话，发送预置请求并等待两路文本记录 | 分发器保留该路径，但相关注释标识为未使用；是否进入本次队列取决于实际选项 |
| A-13 | 继电器恢复路径 | 一个保留的网络测试入口直接跳到完成分支，复位线路并写入通过行 | 该入口未执行完整网络测量，不能把写入的通过行作为独立验收依据 |

### 3.4 记录与结束

结果通过界面信号逐行更新。非循环队列完成后，程序在可执行文件目录的 `data` 子目录中按时间戳保存 `.txt` 结果表。

“停止测试”主要清空队列并解除定时器连接；该函数没有统一关闭电源的调用。部分项目明细状态与汇总通过行使用不同写入逻辑，读取结果时应同时查看分项记录。

### 4.2 实际测试流程


自动入口采用上述固定启动顺序，后续多个线程持续工作。源码中的另一段主流程线程启动代码已被注释，本文未将其专用流程计入当前自动执行链。

### 5.2 实际测试流程

```text
选择测试方式和参与工位，读取资源、通道映射及测试频次
  → 开启台架电源和所选工位供电支路
  → 设置测试显示画面，进行工位通信握手
  → 标记在线状态，建立日志、记录文件和报表
  → 循环：测试项 1～9 为外层，工位 1～8 为内层
  → 到达该项频次条件时，对所选在线工位执行激励和采集
  → 根据函数返回结果维护计数、界面与日志
  → 周期间隙轮换视频通道，继续下一轮
  → 停止时关闭供电路径，调用记录和报表写入，释放相关资源
```

综合测试和环境循环界面都采用逐项、逐工位轮询结构。每项具有运行频次因子，因此每轮不一定执行全部项目。部分分支对连续失败累计后再增加失败次数，统计次数不能直接理解为每次采样的一对一计数。

环境循环界面使用台架现有电气和通信资源；未发现由该流程控制温箱等环境设备的 SDK 调用。

### 6.2 实际测试流程

```text
选择类型和工位
  → 加载协议数据库、对应工位的流程数据库与明细测点
  → 初始化设备，准备供电、离散条件和 1394 通信
  → 勾选项目、设置执行轮数和记录信息
  → 外层按轮次执行，内层按所选项目列表执行
  → 按数据库类名创建的业务对象遍历明细测点
  → 每个测点：查映射／校准 → 设定硬件 → 等待 → 采集 → 判定与记录
  → 必要时重复采样、调整输出或重新供电，再完成该测点
  → 执行该项自身的恢复操作，继续下一项
  → 每轮提交报告生成；全部完成后更新界面和功率支路开关
```

主流程表提供项目 ID、显示名称、执行类和可选子项目关系，明细表提供通道、设定与判定参数。已读取当前三类配置目录中的 30 份工位流程数据库；各工位项目集合不同，因此下表是项目能力的合并清单，不表示某一工位会执行全部编号。

一般项目判为不合格后仍继续所选列表。部分模拟量项目在一次测点内读数、修正输出后重试；部分项目使用多个采样结果。不能将所有业务简化为“设置一次、读取一次”。
