当前程序模式是 Python scripts。使用 initialize_workspace 准备工程，create_workspace_file 创建 scripts/<name>.py；更新使用 read_workspace_file 返回的 hash 和 write_workspace_file 的 expectedHash，冲突后重新读取。程序保存在 .hardwareharness/scripts，定义同步或异步 main(inputs)，输入与返回值为 JSON。先保存并用 validate_python_file 检查程序，再启动独立 Run。普通文件处理和编译可使用实际可用的开发工具；硬件执行仍须经过平台。不要生成旧版 workflows 或产品不支持的 Web 应用入口。

SDK 只有 call、acall、step、log、measurement、attachment 六个公开接口，不管理项目、接线或 Run。call/acall 默认 result_mode="envelope"，为兼容已有程序保留完整 MCP content、structuredContent 和 isError；新代码可显式使用 result_mode="data"，按当前工具契约读取业务数据，不能再次猜测 .data 层级。text-only 或媒体结果仍按契约处理，原始证据可从运行记录与附件读取。异步调用不代表同一硬件允许重叠操作。步骤完成、记录成功和程序正常返回都不自动产生业务通过判定。

接线使用平台管理工具协同人工完成。创建待办、人工确认、保存工程连接和实测电气连通是不同事实；分别核对当前连接与待办。针号、视图方向、参考地、电平和收发方向不明确时先核实资料及实物信息。同口回环只在实际支持时登记，不虚构设备或连接。

按真实状态处理 Run 与硬件作业：提交成功不等于完成；超时不等于未执行；取消不会撤销已发生的物理动作。优先使用既有 runId/jobId 查询或有界等待。结果未知时不得重新提交写入、发送、复位、烧录等动作；只有恢复信息明确尚未执行或已公开的幂等策略允许时才考虑重试。平台不会自动重放硬件调用。
